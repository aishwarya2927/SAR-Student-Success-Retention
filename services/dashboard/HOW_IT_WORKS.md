# Faculty Dashboard API — Reference for Person D

The Faculty Dashboard stores intervention and placement plans generated by the Mentor Agent and lets faculty approve or reject them. Only **approved** plans are exposed to the Student Agent via this API.

**Base URL (deployed):**
```
https://sar-student-success-retention-3kvj.onrender.com
```

Use this URL directly — there is no local setup required on your end. This is a live, publicly deployed service.

---

## How Approved Plans Reach You

```text
Faculty reviews a generated plan (intervention or placement)
        │
        ├──── Approve ──── status = approved  → visible via this API
        │
        └──── Reject  ──── status = rejected  → never returned by this API
```

---

## GET `/intervention/{student_id}`

Returns the most recently approved intervention plan for a student.

**Example Request:**
```
GET https://sar-student-success-retention-3kvj.onrender.com/intervention/STU202600001
```

**Success Response — 200:**
```json
{
  "intervention_id": 1,
  "student_id": "STU202600001",
  "risk_band": "High",
  "prediction_confidence": 87.5,
  "student_summary": "Student has poor attendance and multiple backlogs.",
  "recommended_actions": [
    "Schedule counseling session",
    "Refer to tutoring center"
  ],
  "priority_level": "urgent",
  "follow_up_plan": "Follow up in 2 weeks to assess improvement.",
  "status": "approved",
  "approved_by": "Dr. Sharma",
  "approved_at": "2026-07-04 10:44:59",
  "generated_at": "2026-07-04 10:44:34"
}
```

**Not Found — 404:**
```json
{
  "detail": "No approved intervention found for student STU202600001"
}
```

## GET `/placement/{student_id}`

Returns the most recently approved placement plan for a student. Note: the Mentor Agent fetches `target_companies` directly from your endpoint at generation time — this field in the response reflects whatever companies were current **at the moment this specific plan was generated**, not necessarily the student's current selection if they've changed it since.

**Example Request:**
```
GET https://sar-student-success-retention-3kvj.onrender.com/placement/STU202600058
```

**Success Response — 200:**
```json
{
  "placement_id": 1,
  "student_id": "STU202600058",
  "target_companies": [],
  "readiness_summary": "This student is currently in a high risk band primarily due to four backlogs and a notable financial stress score...",
  "company_comparison": "",
  "company_selection_guidance": "To identify target companies, begin by researching industries and roles that highly value AI/ML skills...",
  "preparation_steps": [
    {
      "title": "Resolve Outstanding Backlogs",
      "duration": "2-4 weeks (immediate)",
      "priority": "primary",
      "detail": "Immediately prioritize clearing all four outstanding backlogs..."
    }
  ],
  "timeline": "Your immediate timeline over the next 2-3 months should focus on clearing all backlogs...",
  "risk_factors": [
    {
      "risk": "backlog_count",
      "action": "Prioritize and clear all four outstanding academic backlogs immediately."
    }
  ],
```

## GET `/health`

Verify the API is reachable before making calls.

**Response:**
```json
{"status": "ok", "service": "dashboard-api"}
```

---

## Field Notes

| Field | Type | Notes |
|---|---|---|
| `recommended_actions` (intervention) | list | Always a proper list — safe to iterate directly |
| `preparation_steps` (placement) | list of objects | Each has `title`, `duration`, `priority`, `detail` |
| `risk_factors` (placement) | list of objects | Each has `risk` and `action` |
| `target_companies` (placement) | list | May be empty — see `data_verification_note` when it is; reflects companies at generation time, not necessarily current |
| `status` | string | Always `"approved"` — pending/rejected are never returned |
| `approved_at` / `generated_at` | string | Format: `YYYY-MM-DD HH:MM:SS` |
| `prediction_confidence` (intervention) | float | Confidence score from the Risk Engine — indicates how sure the model is about the risk_band classification, not the severity of risk itself |

- Always handle the 404 case — a plan may not be approved yet for a given student.
- Only the **most recently approved** plan is returned for each endpoint, even if a student has multiple approval records in history.
- Do not pass `status` as a query filter — the API already only returns approved plans.
- **Recommended check on your side:** since `target_companies` in a placement response is a snapshot from generation time, consider comparing it against your own current record of the student's target companies. If they differ, the plan may be based on outdated selections — consider flagging this to the student (e.g., "this plan may not reflect your current target companies") rather than presenting it as fully current.

---

## Error Handling

| Scenario | Result |
|---|---|
| Invalid or unknown student ID | 404 |
| No approved plan exists yet | 404 |
| Dashboard API not running | Connection error on your side — check `/health` first (should not happen in production; the API is deployed continuously on Render) |
